=== MAJOR PIVOT (2026-09-09) ===
This project was previously a "first at-bat reach base" prediction pipeline. On 2026-09-09 it was
completely repurposed to focus exclusively on YRFI/NRFI betting:

  YRFI = Yes Run First Inning  — a run is scored in the 1st inning by either team
  NRFI = No Run First Inning   — no run is scored in the 1st inning

Single question the whole project answers: will a run be scored in the first inning of this game?
The old first-at-bat model, its three blended sub-models, and the old dashboard were scrapped
(moved to data/archive/ and src/archive/, nothing deleted).

Critical technical requirement: Use /Library/Frameworks/Python.framework/Versions/3.14/bin/python3
for all python commands and /Library/Frameworks/Python.framework/Versions/3.14/bin/streamlit for all
streamlit commands. Do not use the venv. Packages are installed in system Python only. Start
Streamlit with --server.headless true.

=== ARCHITECTURE ===

Ground truth: first-inning runs come from the official MLB Stats API linescore
(statsapi.mlb.com/api/v1/schedule?sportId=1&season=YYYY&gameType=R&hydrate=linescore,probablePitcher —
one HTTP call per season). 27,408 games 2015-2026, overall YRFI rate ~50.5% (matches published
league figure).

Model: a single game-level RandomForestClassifier (n=600, depth=12, leaf=25, class_weight=balanced)
+ isotonic CalibratedClassifierCV, predicting P(YRFI) per game. Time split: train 2015-2022,
validate 2023, test 2024; final production fit uses 2015-2024 + calibrates on 2025. Test AUC ~0.555
(YRFI is a near-coinflip event; published NRFI models sit 0.55-0.62). Well calibrated (test ECE ~0.04).
A logistic-regression SURROGATE is trained alongside it (test AUC ~0.58) purely to give an additive
log-odds decomposition for the dashboard's ⚙️ weighting sliders — it never replaces the RF output.

Feature groups (src/yrfi_features.py :: build_game_features; slider groups in FEATURE_GROUPS):
  - home/away starting pitcher first-inning profile: career/season/L5 NRFI%, 1st-inn ERA, K rate,
    BB rate, hard-hit% allowed, first-pitch-strike rate, avg velo, primary pitch code
  - away/home projected top-5 batter aggregates: OBP vs today's pitcher (BvP), avg BvP sample,
    L7 OBP, L30 OBP, season HR/PA, hard-hit%, power score
  - park factors (run factor, HR factor, dome flag) from src/park_factors.py
  - weather (temp, wind speed, wind-out component, humidity — dome games forced neutral)
  - month, umpire zone adjustment

KNOWN MODEL CAVEATS (in yrfi_model_meta.json):
  - Pitcher NRFI profiles and top-5 batter aggregates are CURRENT static values, not point-in-time,
    so career features carry mild look-ahead bias; test AUC is a small over-estimate.
  - Historical top-5 batter aggregates use 2026 projected lineups (team-level approximation).
  - umpire_zone_adj is a placeholder (0.0) for almost all games — game_meta has no real per-umpire
    zone data yet.
  - Isotonic calibration + limited feature spread makes today's probabilities cluster onto a handful
    of distinct values.
  - batter_rolling.parquet (statcast) is stale at 2026-06-01, so the top-5 hard-hit%/xBA/BB% detail
    is old; the OBP/OPS/R/AB windows come from batter_game_logs.parquet (current).

=== DASHBOARD (app.py) ===
Completely rewritten 2026-09-09. Streamlit on localhost:8501. Single page, two views:

LANDING (game list):
  - ⚙️ Model weighting expander at the very top: one slider (0-200%, default 100%) per feature group
    — Pitcher NRFI track record, Pitcher stuff, Pitcher last-5, Lineup power/matchup, Lineup recent
    form, Ballpark, Weather. Each shows a "current lean" bar = how much the model already leans on
    that group. 100% reproduces the model exactly; the sliders scale each group's log-odds
    contribution around the model's own prediction (does NOT need to sum to 100%). "Reset to model"
    button (uses st.session_state.pop of the widget keys — you cannot assign a widget key after the
    widget is drawn). When any slider != 100% every card, edge, EV and recommendation recomputes
    live and shows "model X% → your Y%".
    "Effective weighting right now" — a live stacked colour bar + legend UNDER the sliders showing
    each group's share = (slider% × the model's lean) renormalised to 100%. Recomputes instantly
    on every slider move.
    Mechanism: a logistic-regression surrogate trained alongside the RF in src/13 gives per-feature
    log-odds; src/14 sums them by group into contrib_<group> columns + base_model_logit;
    app.apply_weights() does adj_logit = base + Σ (w_g-1)·contrib_g.
  - Header: title, date/time, colour-coded "updated N min ago" (green <30m / yellow <120m / red older),
    "Refresh slate" button (runs the 5-step daily sequence with a live status panel).
  - Metric row: Games today · Strong NRFI edges (>4%) · Strong YRFI edges (>4%) · Confirmed starters.
  - Filters: All / NRFI Edge / YRFI Edge / No Edge · sort (Edge% / Game Time / Home / Away) ·
    confirmed-starters-only toggle.
  - One card per game (3 columns):
      LEFT   — the two teams stacked tight: team logo (mlbstatic.com/team-logos/{team_id}.svg) +
               abbr + W-L record + probable pitcher + that pitcher's season/L5 NRFI%; then a
               park · weather · confirmed-status line.
      MIDDLE — MODEL block: BOTH model odds shown (NRFI and YRFI) with the better-value side in
               bold + a ◄ marker (better value = side with the higher market edge, or the model
               favourite when no odds).
      RIGHT  — BOOK LINES: a 2×4 table (NRFI / YRFI rows × DK / FD / MGM / CZR). Every listed odds
               cell is a link (new tab): ⚡ = per-selection add-to-betslip deeplink — CZR & MGM
               ONLY; ↗ = the book's MLB lobby — DK (no deeplink) and FD (SGO's deeplink uses a
               generic template selectionId that FanDuel rejects, so it's dropped). Plus a
               "checked {Mon D, H:MM AM}" timestamp from odds_checked_at and a one-line note
               spelling out which books support ⚡.
    Below: recommended-bet badge (✅ BET NRFI / ✅ BET YRFI / 📈 MODEL / ⚪ NO EDGE) · edge% ·
    EV/$100 · "best {Book} {odds}⚡/↗" · "View details →".
    When ⚙️ custom weights are active the MIDDLE block header reads "⚙️ YOUR WEIGHTING" and each
    row shows "(model X%)".
  Detail view Section 1 also has a row of side-aware betslip buttons "⚡/↗ {Book} {SIDE} {odds}"
  for the recommended/better-value side + a "⚡ Add {SIDE} to {Book} betslip" button under the
  Best Bet box (only when that book's link is a real deeplink).
  app.py helpers: _bet_url() resolves the deeplink-or-lobby URL + instant flag; _better_value_side();
  apply_weights() re-derives every probability/odds/edge/EV/recommendation from the sliders.
  - Sidebar: model test AUC / Brier / ECE / accuracy + caveats (incl. the ⚡ book / geo caveat).
  - todays_yrfi_predictions.parquet also carries home_team_id / away_team_id, home_team_record /
    away_team_record (MLB standings, 1 call in src/14), odds_checked_at, base_model_logit,
    contrib_<group> (surrogate log-odds per slider group).
